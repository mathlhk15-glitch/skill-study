# class-slide-maker · 메타 스타일 수업용 슬라이드 빌더

## 스킬 개요
슬라이드 개요(순서가 있는 항목 목록)를 받아 **화이트 캔버스 + 코발트 블루(#0064E0) 포인트**의
메타 디자인 시스템 스타일 PPTX를 생성한다. 리포트형 원본 스타일과 달리 **한 슬라이드 = 한 메시지**
원칙으로 정보 밀도를 낮추고 폰트를 키워 교실 뒷자리에서도 잘 보이게 만든다.

**슬라이드 장수는 사용자가 준 개요 항목 수와 항상 일치한다.** 임의로 슬라이드를 추가하거나 합치지 않는다.

---

## 1단계: 개요 수집
사용자에게 다음을 받는다(대화에 이미 있으면 다시 묻지 않는다):
1. **전체 제목/과목/차시** (표지용)
2. **슬라이드별 개요** — 각 항목마다:
   - 무슨 내용인지 (제목 한 줄 + 핵심 포인트)
   - 어떤 형태가 어울리는지 힌트가 있으면 반영, 없으면 Claude가 내용에 맞는 타입을 판단
   - 이미지가 필요한 자리인지 여부

개요가 러프한 문장/목차 형태로 와도 괜찮다 — Claude가 아래 8개 타입 중 가장 적합한 것으로
직접 분류해서 `content.json`을 만든다. 항목 수가 곧 슬라이드 수이므로, 사용자가 "5장으로",
"목차 항목마다 한 장씩" 이라고 하면 그 개수를 그대로 따른다.

## 2단계: 슬라이드 타입 선택
`references/layout_types.md`에 8개 타입과 JSON 스키마가 정의되어 있다. 내용 성격에 맞게 고른다:

| 내용 성격 | 타입 |
|---|---|
| 표지/도입 | `cover` |
| 목표·핵심 포인트 나열 | `bullets` |
| A vs B, 전/후 비교 | `compare` |
| 순서가 있는 절차·단계 | `process` |
| 구조화된 수치/항목 비교표 | `table` |
| 사진·실습 장비·결과물 중심 | `image` |
| 발문·명언·핵심 한 줄 강조 | `quote` |
| 정리·질문·다음 차시 예고 | `closing` |

`references/meta_style.md`에는 색상 토큰·폰트 크기·디자인 규칙이 정리되어 있다(스크립트에 이미
내장되어 있으므로 직접 색을 지정할 필요는 없다 — 내용만 채우면 됨).

## 3단계: content.json 작성
`assets/content.example.json`을 참고해 실제 `content.json`을 작성한다.
- `slides` 배열 순서 = 최종 슬라이드 순서
- 이미지가 필요하면 `image`(실제 파일명) 또는 `showImageSlot: true`(자리만) 지정
- 불릿은 2~6개, 표는 6행 이하, 프로세스는 3~5단계 권장(가독성 유지)

## 4단계: PPTX 생성
```bash
node /mnt/skills/user/class-slide-maker/assets/build_deck.js content.json [imgDir] output.pptx
python /mnt/skills/public/pptx/scripts/rezip.py output.pptx   # 필수
```
- `imgDir`은 생략 시 `img` 폴더를 찾는다(없어도 오류 없이 자리 표시로 대체됨).
- 사용자가 실제 이미지를 첨부했다면 `imgDir`에 저장 후 `content.json`의 `image` 필드에 파일명을 지정.

## 5단계: QA (필수)
```bash
python /mnt/skills/public/pptx/scripts/office/soffice.py --headless --convert-to pdf output.pptx
rm -f slide-*.jpg
pdftoppm -jpeg -r 130 output.pdf slide
```
모든 슬라이드를 `view`로 열어 확인:
- 제목이 길어 2줄로 넘어갈 때 부제/본문과 겹치지 않는지 (자동 계산되지만 매우 긴 제목은 확인 필요)
- 텍스트가 박스를 벗어나지 않는지
- 표/프로세스 항목 수가 많아 글자가 너무 작아지지 않았는지
- 페이지 번호가 `undefined` 등으로 깨지지 않았는지

문제 발견 시 `content.json` 내용을 조정(문장 길이 줄이기, 항목 수 줄이기)하거나 필요 시
`assets/build_deck.js`의 좌표를 조정한 뒤 재검수. 사소한 픽셀 단위 조정은 반복하지 않는다.

## 6단계: 제공
`present_files`로 pptx 전달. 파일명 예: `[주제]_슬라이드.pptx`.
간단히 몇 장으로 구성됐는지, 어떤 타입을 썼는지 한두 줄로 안내.

## 주의사항
- hex 색상에 `#` 금지 (스크립트 내부는 이미 준수하고 있음 — 직접 수정 시에도 지킬 것)
- 완성 후 **rezip 필수**
- 실존 사진을 임의로 생성하지 않는다 — 항상 자리 표시(placeholder)만 제공
- 슬라이드 장수를 임의로 늘리거나 줄이지 않는다 — 개요 항목 수 = 슬라이드 수
- 폰트는 `Pretendard`(미설치 환경에서는 시스템 고딕으로 자동 대체되어 QA 미리보기와 실제 PPT가
  약간 다를 수 있음 — 텍스트 박스 벗어남 여부만 확인하면 충분)
